1. 阶段 1：论文全局认识

1.1 标题（Title）

1.1.1 准确翻译

AnySplat：从无约束视角进行前馈式 3D Gaussian Splatting。

也可以更完整地表达为：

AnySplat：面向无约束图像视角集合的前馈式三维高斯泼溅重建。

1.1.2 核心术语

Feed-forward

指训练完成后，输入一组图像，通过一次模型前向计算直接预测场景表示，而不是像传统 3DGS 那样针对每个测试场景执行大量迭代优化。

这里的 feed-forward 不意味着整个系统永远没有优化：论文还提供了可选的 test-time post-optimization。必须区分：

  • AnySplat 基础模型：前馈预测；
  • AnySplat + Post Optimization：前馈初始化后再进行场景级优化。

3D Gaussian Splatting

使用一组具有位置、方向、尺度、不透明度和颜色属性的三维 Gaussian 表示场景，通过可微 Gaussian rasterization 生成图像。

Unconstrained Views

本文语境下的关键含义是：输入图像不要求预先提供相机内外参，输入视图也不被限制为固定的两视图或少量特定排列。模型需要从图像集合中联合推断相机参数和三维场景。

它并不意味着完全没有约束：

  • 输入图像仍需来自同一个场景；
  • 方法依赖预训练几何先验；
  • 场景动态变化、强反射和细薄结构仍可能失败；
  • 多视图几何恢复仍需要足够的有效观测信息。

Pose-free / Uncalibrated

本文的输入是未标定图像集合，模型同时预测各输入图像的相机内参和外参。

这与 PixelSplat、MVSplat、DepthSplat 的常见设定有重要区别：后三者的主要方法流程需要相机参数来构建跨视图几何关系，而 AnySplat 将相机估计纳入前馈网络本身。

1.1.3 标题指向的研究任务

从标题可以确定：

  1. 输入是多视图图像；
  2. 输入不要求已知相机标定；
  3. 输出是 3D Gaussian 场景表示；
  4. 目标是前馈式三维重建与新视角合成。

但标题本身不能确定：

  • 相机内参和外参如何编码；
  • 是否使用预训练几何基础模型；
  • 如何处理密集输入视图；
  • 是否需要伪标签；
  • 是否存在测试时优化；
  • 对极稀疏视图的几何可辨识性如何处理。

这些需要由 Method 和 Experiments 确认。

1.2 摘要（Abstract）

1.2.1 研究背景

作者指出，传统 neural rendering pipeline 需要已知相机位姿，并且通常需要逐场景优化。

另一方面，近期前馈方法在密集输入视图时会受到计算开销限制。

1.2.2 目标问题

作者希望实现：

从未标定图像集合直接进行 Novel View Synthesis，并且在输入视图数量从稀疏到密集变化时保持可用。

1.2.3 核心方法

作者提出 AnySplat：

  • 输入 uncalibrated image collection；
  • 一次前向预测 3D Gaussian primitives；
  • 同时预测每张输入图像的 camera intrinsics and extrinsics；
  • 使用统一模型处理稀疏与密集视图。

1.2.4 主要结果主张

作者声称：

  • 在 sparse-view 和 dense-view 场景中，达到与 pose-aware baseline 相当的质量；
  • 超过已有 pose-free 方法；
  • 相比逐场景优化的 neural fields，显著降低重建和渲染延迟。

1.2.5 摘要逻辑概括

论文试图解决的不是单纯的 Gaussian 参数预测，而是三个相互关联的问题：

  1. 未知相机参数时，如何从图像集合恢复场景；
  2. 输入视图数量增加时，如何控制 Gaussian 数量和渲染开销；
  3. 只有 RGB 图像而缺少真实 3D 标注时，如何稳定训练联合相机—几何预测模型。

摘要主张不等于独立证明。 这些内容需要分别由相机估计实验、密集视图实验、消融实验和训练细节支撑。

1.3 核心贡献（Contributions）

作者在 Introduction 中明确列出三项贡献。

Contribution 1：Feed-forward reconstruction and rendering

作者主张：

模型接收未标定多视图输入，同时预测 3D Gaussian primitives 与相机内外参，从而实现前馈式重建和渲染。

针对的问题：

传统逐场景优化依赖相机标定和大量优化迭代；已有 pose-free 方法主要局限于稀疏视图。

对应方法：

  • Geometry Transformer；
  • Camera Pose Prediction；
  • Pixel-wise Gaussian Parameter Prediction；
  • Differentiable Voxelization。

主要证据：

  • Table 1：稀疏与密集视图 NVS；
  • Table 2：200-view MatrixCity；
  • Table 3：16-view Mip-NeRF360；
  • Table 4：相机位姿估计；
  • Figures 3、4、6、9、11、12。

Contribution 2：Efficient pseudo-label knowledge distillation

作者主张：

从预训练 VGGT 中蒸馏几何与相机先验，仅使用 RGB 图像训练 AnySplat，不依赖真实 3D SfM 或 MVS 标注。

针对的问题：

只使用输入图像重建损失时，模型可能过拟合输入视图，得到外观合理但几何不可靠的结果。

对应方法：

  • VGGT pseudo camera poses；
  • VGGT pseudo depth；
  • Camera pose distillation loss；
  • Geometry distillation loss；
  • Geometry consistency loss。

主要证据：

  • Table 4；
  • Table 5；
  • Figure 8；
  • Section 4.3。

Contribution 3：Differentiable voxel-guided Gaussian pruning

作者主张：

通过可微体素化，将像素级 Gaussian 聚合成体素级 Gaussian，减少约 30–70% 冗余 Gaussian，同时保持渲染质量。

针对的问题：

传统每像素一个 Gaussian 的方式，在输入视图数量超过 32 后，Gaussian 数量和显存开销持续增加。

对应方法：

  • 3D voxel assignment；
  • Per-Gaussian confidence；
  • Intra-voxel softmax weighting；
  • Attribute aggregation。

主要证据：

  • Figure 5；
  • Table 5；
  • Table 1；
  • Figure 6。

1.4 结论（Conclusion）

作者明确得出的结论

  1. AnySplat 可以从未标定图像集合前馈预测 Gaussian 场景和相机参数。
  2. 方法在 sparse-view 和 dense-view 两类重建任务中取得有竞争力的结果。
  3. VGGT 伪标签蒸馏与几何一致性增强能够改善训练稳定性和多视图几何。
  4. Differentiable Voxelization 能够减少冗余 Gaussian，并缓解密集视图下的渲染显存增长。
  5. 前馈模型能够在数秒量级完成场景重建，具有交互式 3D 应用潜力。

作者明确承认的局限

  • 天空区域；
  • 镜面高光；
  • 细薄结构；
  • 动态场景；
  • 光照变化；
  • 高分辨率和大量输入视图带来的计算—分辨率权衡。

Future Work

作者提出：

  • 提升 patch size 灵活性；
  • 增强对重复纹理的鲁棒性；
  • 扩展到数千张高分辨率输入。

Caption 原文要点：

+
\text{Depth}

\text{Gaussian Attributes}.

3. 阶段 3：正文逐层精读

3.1 研究问题（Problem Setup）

3.1.1 输入

给定同一场景的 (N) 张未标定图像：

[
{I_i}_{i=1}^{N},
\qquad
I_i\in\mathbb{R}^{H\times W\times 3}.
]

论文的核心设定是：

  • 不预先提供相机内参；
  • 不预先提供相机外参；
  • 输入图像数量可以从稀疏到密集变化；
  • 模型需要从图像集合中联合恢复场景与相机参数。

3.1.2 输出一：3D Gaussian 集合

[
\left{
(\boldsymbol{\mu}g,\sigma_g,\boldsymbol r_g,
\boldsymbol s_g,\boldsymbol c_g)
\right}{g=1}^{G}.
\tag{1}
]

其中：

  • (\boldsymbol{\mu}_g\in\mathbb R^3)：Gaussian 中心；
  • (\sigma_g\in\mathbb R^+)：正 opacity 参数；
  • (\boldsymbol r_g\in\mathbb R^4)：orientation quaternion；
  • (\boldsymbol s_g\in\mathbb R^3)：anisotropic scale；
  • (\boldsymbol c_g\in\mathbb R^{3\times(k+1)^2})：球谐颜色系数。

这里的 (\sigma_g) 是论文使用的符号，不要与其他论文中常用的 opacity (\alpha) 符号混淆。

3.1.3 输出二：相机参数

[
{p_i\in\mathbb R^9}_{i=1}^{N}.
\tag{2}
]

论文说明 (p_i) 编码第 (i) 张图像的相机内参与外参。

原文没有在 Problem Setup 中进一步逐项拆解这 9 个维度的具体参数化，因此不能仅凭维度自行断言每一维对应什么。

3.1.4 整体映射

[
f_{\boldsymbol\theta}:
{I_i}{i=1}^{N}
\longmapsto
\left{
(\boldsymbol{\mu}g,\sigma_g,\boldsymbol r_g,
\boldsymbol s_g,\boldsymbol c_g)
\right}{g=1}^{G}
\cup
{p_i}{i=1}^{N}.
\tag{3}
]

这意味着 AnySplat 需要联合学习：

  1. 图像到几何；
  2. 图像到相机；
  3. 几何与外观到可渲染场景表示。

作者还指出模型可产生 global point map、per-frame depth maps 和 confidence scores 等副产物。

3.2 整体方法架构

3.2.1 总体数据流

最关键的是：AnySplat 的相机、深度和 Gaussian 属性不是三个独立任务的简单拼接，而是共同服务于同一个三维场景表示。

3.3 Geometry Transformer

【原文：Section 3.2】

3.3.1 Patch Embedding

作者沿用 VGGT 的几何 Transformer 设计。

每张图像使用 DINOv2 patch embedding：

  • Patch size：(p=14)；
  • Token dimension：(d=1024)；
  • 图像 token 数量：

[
l_I=\frac{HW}{p^2}.
]

每张图像得到：

[
t_i^I\in\mathbb R^{l_I\times d}.
]

3.3.2 Camera Token 与 Register Tokens

对每张图像，额外加入：

  • 一个 learnable camera token：

[
t_i^g\in\mathbb R^{1\times d};
]

  • 四个 register tokens：

[
t_i^R\in\mathbb R^{4\times d}.
]

因此每张图像的 token 序列为：

[
[t_i^I;t_i^g;t_i^R].
]

论文还说明：对于第一张输入图像，这些 token 不添加 positional encodings。

3.3.3 Alternating Attention

所有视图的 tokens 被送入 (L)-layer Alternating-Attention Transformer。

每层包含两种注意力：

Frame Attention

先对每张图像内部的 token 进行 attention：

[
\mathbb R^{N\times(l_I+5)\times d}.
]

Global Attention

随后把所有视图 token 合并，在全局范围执行 attention：

[
\mathbb R^{1\times N(l_I+5)\times d}.
]

因此：

  • Frame Attention：建模单张图像内部的视觉结构；
  • Global Attention：在不同视图之间交换信息。

实现细节中，作者设置：

[
L=24.
]

独立分析：

这套设计使模型能够从多视图中联合推断几何和相机，但 Global Attention 的 token 数量随输入视图数增长。Differentiable Voxelization 只压缩输出 Gaussian，并不能直接消除 Transformer 对大量输入 tokens 的注意力计算成本。

3.4 Camera Pose Prediction

【原文：Section 3.2】

Transformer 更新后的 camera tokens：

[
\hat t_i^g
]

输入 Camera Decoder：

[
F_C.
]

该模块包含：

  • 四个额外 self-attention layers；
  • 一个 linear projection head。

最终预测每张图像的相机参数：

[
p_i.
]

作者将第一张图像的相机设为 identity transformation，其余相机均在该共享局部坐标系中表达。

重要边界：

固定第一张相机为 identity 是一种坐标系 gauge fixing，并不自动意味着恢复了真实世界坐标或绝对尺度。

3.5 Pixel-wise Gaussian Parameter Prediction

【原文：Section 3.2】

作者使用双 Head 设计：

  • Depth Head (F_D)；
  • Gaussian Head (F_G)。

3.5.1 Depth Head

输入：

[
\hat t_i^I.
]

输出：

[
(D_i,C_i^D)=F_D(\hat t_i^I).
]

其中：

  • (D_i)：每张图像的 per-pixel depth；
  • (C_i^D)：深度置信度。

深度图结合预测相机参数反投影：

[
{\boldsymbol\mu_g}

\operatorname{proj}({p_i},{D_i}).
]

因此 Gaussian 中心直接依赖：

  1. 深度预测；
  2. 相机内参；
  3. 相机外参。

这意味着 pose error 与 depth error 会共同影响三维几何。

3.5.2 Gaussian Head

Gaussian Head 结合两类特征：

DPT Features

[
F_d(\hat t^I).
]

Appearance Features

[
F_a(I).
]

其中 (F_a) 是浅层 CNN 提取的图像外观特征。

二者相加后输入回归 CNN：

[
F_b.
]

输出：

[
{\sigma_g,\boldsymbol r_g,\boldsymbol s_g,
\boldsymbol c_g,C_g}.
]

其中 (C_g) 是每个 Gaussian 的 confidence。

注意：这里存在两种不同的 confidence：

  • (C_i^D)：Depth Head 的像素级置信度，用于几何一致性损失中的高置信区域筛选；
  • (C_g)：Gaussian 级置信度，用于 voxel 内 Gaussian 属性聚合。

不能将两者混为一谈。

3.6 Differentiable Voxelization

【原文：Section 3.2，Equations (5)–(7)】

3.6.1 为什么需要体素化？

传统前馈 3DGS 常采用 one Gaussian per pixel。

如果输入 (N) 张图像，每张分辨率为 (H\times W)，初始 Gaussian 数量大致为：

[
G\approx NHW.
]

因此，随着输入视图增加，Gaussian 数量近似线性增长。

作者希望将空间位置接近的 Gaussian 聚合起来。

3.6.2 Voxel Assignment

定义 voxel size：

[
\epsilon.
]

将 Gaussian 中心按体素尺度量化：

[
{V_s}_{s=1}^{S}

\left\lfloor
\frac{{\boldsymbol\mu_g}_{g=1}^{G}}{\epsilon}
\right\rceil.
\tag{5}
]

其中 (\lfloor\cdot\rceil) 表示取最近整数的量化操作。

每个 Gaussian 根据其中心坐标被分配到某个 voxel。

实验设置：

[
\epsilon=0.002.
]

3.6.3 Intra-voxel Confidence Weight

对同一 voxel 内的 Gaussian，使用 confidence 进行 softmax：

[
w_{g\rightarrow s}

\frac{\exp(C_g)}
{\sum_{h:V_h=s}\exp(C_h)}.
\tag{6}
]

因此，同一 voxel 内 confidence 较高的 Gaussian 会获得更大的权重。

3.6.4 Attribute Aggregation

对 Gaussian 属性 (a_g)，例如 opacity 或 color：

[
\bar a_s

\sum_{g:V_g=s}
w_{g\rightarrow s}a_g.
\tag{7}
]

作者将 Gaussian 参数聚合到 voxel-level representation。

最终输出 voxel-wise Gaussians。

3.6.5 这一步真正解决了什么？

它主要解决：

  • 同一空间区域中来自不同视图的冗余 Gaussian；
  • 输入视图增加导致的 Gaussian 数量膨胀；
  • 后续 Gaussian rasterization 的显存开销。

3.6.6 关于 Differentiable 的技术边界

【独立评价】

Eq. (5) 中的 voxel membership 通过取整进行离散分配；Eq. (6)–(7) 的 confidence weighting 和属性聚合则是可微的。

因此，从公式本身看：

  • voxel membership 的离散变化并非普通意义下处处可微；
  • 固定 voxel assignment 后，权重和属性聚合可通过网络参数反向传播；
  • 如果要对跨 voxel 边界的 assignment 本身求连续梯度，需要额外机制，但本文正文没有明确展开这部分。

所以更严谨的理解是：作者通过 confidence-weighted aggregation 构造可训练的体素级 Gaussian 聚合，而不是简单地把所有离散空间量化操作都理解成处处可微。

3.7 Geometry Consistency Enhancement

【原文：Section 3.3】

3.7.1 为什么需要几何一致性？

作者指出，同时预测深度与相机位姿会带来多视图对齐误差。

每张图像的 depth map 被反投影到三维后，可能形成：

  • layered sheets；
  • 不一致的表面；
  • 不同视图间错位的几何结构。

这些问题在 point cloud 中可能不明显，但在 novel-view rendering 中会产生明显伪影。

3.7.2 Depth Head 与 Rendered Depth 对齐

定义：

  • (D_i)：Depth Head 输出的深度；
  • (\hat D_i)：Gaussian 渲染得到的深度；
  • (M)：高置信度像素 mask。

几何一致性损失：

[
\mathcal L_g

\frac{1}{N}
\sum_{i=1}^{n}
(D_i[M]-\hat D_i[M])^2.
\tag{8}
]

作者使用 Depth Head 的 confidence map (C_i^D)，只对最高置信度的 30% 像素施加监督：

[
N=30%.
]

这里的 (N) 在论文公式中还被用作输入视图数量，符号复用容易造成歧义；实际语义应根据上下文理解为 confidence quantile。

3.7.3 为什么只监督高置信度区域？

作者指出，天空、反射表面等区域的深度预测可能不可靠。

如果直接对所有像素施加深度一致性约束，可能把错误深度强行写入 Gaussian 几何。

因此选择 top 30% confidence pixels。

独立评价：

这是一种基于模型自身 confidence 的筛选机制，但不等同于 confidence 已经被校准为真实概率。它说明模型会选择相对可信的区域，而不证明其 confidence 与实际几何误差之间具有严格统计一致性。

3.8 Pseudo-label Knowledge Distillation

【原文：Section 3.3，Equations (9)–(10)】

作者观察到，仅使用输入视图重建损失时，模型可能过拟合 context views，产生外观合理但相机和几何不可靠的结果。

因此引入预训练 VGGT 作为几何教师。

3.8.1 Camera Pose Distillation

令：

  • (p_i)：AnySplat 预测相机参数；
  • (\tilde p_i)：VGGT 产生的伪标签相机参数。

损失：

[
\mathcal L_p

\frac{1}{N}
\sum_{i=1}^{N}
|\tilde p_i-p_i|_\epsilon.
\tag{9}
]

其中 (|\cdot|_\epsilon) 表示 Huber loss。

该损失将 AnySplat 的相机预测拉向 VGGT 提供的伪相机先验。

3.8.2 Geometry Distillation

令：

  • (\tilde D_i)：VGGT pseudo depth；
  • (\hat D_i)：Gaussian rendering 得到的深度；
  • (M)：高置信度 mask。

损失：

[
\mathcal L_d

\frac{1}{N}
\sum_{i=1}^{n}
(\tilde D_i[M]-\hat D_i[M])^2.
\tag{10}
]

注意：这里对齐的是 VGGT pseudo depth 与 Gaussian rendered depth，而不是简单地将 VGGT 深度直接当作最终输出。

3.8.3 三种几何约束的关系

损失 对齐对象 主要作用
(\mathcal L_g) AnySplat Depth Head vs Gaussian rendered depth 约束模型内部深度与三维表示一致
(\mathcal L_p) AnySplat camera vs VGGT pseudo camera 约束相机估计
(\mathcal L_d) Gaussian rendered depth vs VGGT pseudo depth 约束三维几何接近教师先验

Gaussian rendered depth 在 (\mathcal L_g) 与 (\mathcal L_d) 中起到桥梁作用：

[
D_{\mathrm{head}}
\leftrightarrow
D_{\mathrm{render}}
\leftrightarrow
D_{\mathrm{VGGT}}.
]

这也是 AnySplat 能够将 RGB-only 原始训练数据转化为几何学习信号的重要机制。

3.9 Training Objective

【原文：Section 3.3，Equation (11)】

3.9.1 RGB Reconstruction Loss

[
\mathcal L_{\mathrm{rgb}}

\operatorname{MSE}(I,\hat I)
+
\lambda_1\operatorname{Perceptual}(I,\hat I).
]

其中：

  • (I)：输入图像；
  • (\hat I)：Gaussian 渲染图像；
  • MSE：像素级重建；
  • Perceptual：感知损失。

3.9.2 总损失

[
\mathcal L

\mathcal L_{\mathrm{rgb}}
+
\lambda_2\mathcal L_g
+
\lambda_3\mathcal L_p
+
\lambda_4\mathcal L_d.
\tag{11}
]

实现权重：

[
\lambda_1=0.05,\quad
\lambda_2=0.1,\quad
\lambda_3=10.0,\quad
\lambda_4=1.0.
]

3.9.3 训练时是否使用 Novel Views？

论文明确说明：训练时仅使用 context views，不提供 novel views 作为训练监督。

模型预测输入视图的相机和 Gaussian，然后渲染回这些输入视图：

[
{I_i}
\rightarrow
{\hat I_i}.
]

训练监督由：

  • 输入图像 RGB 重建；
  • 深度—渲染几何一致性；
  • VGGT pseudo camera；
  • VGGT pseudo depth；

共同构成。

这点很重要：AnySplat 的 Novel View Synthesis 能力并不是通过训练时大量随机 target-view photometric loss 直接建立的，而是依赖多视图几何模型、教师伪标签和统一 Gaussian 表示的泛化能力。

3.9.4 “无 3D 监督”应该如何理解？

作者说训练不需要 3D SfM 或 MVS supervision。

但它仍然使用 VGGT 产生的 pseudo geometry labels。

因此：

  • 不需要人工或数据集提供的真实 3D 几何标签；
  • 不需要传统 SfM/MVS pipeline 产生的标注；
  • 仍然依赖预训练模型提供的相机和深度伪标签；
  • 也依赖 RGB reconstruction loss。

更准确的说法是：

No ground-truth 3D annotation, but with pretrained-model pseudo-geometry supervision.

3.10 Test-time Camera Pose Alignment

【原文：Section 3.3】

论文特别说明，该操作只用于计算 rendering metrics。

测试时涉及：

  • context views (\mathcal I_c)；
  • target views (\mathcal I_t)；
  • 两者不相交。

作者假设：

[
\mathcal I_c\cap\mathcal I_t=\emptyset.
]

通过分别处理 context views 与 context+target views，估计平均尺度：

  • (s)：context views 的平均 scale factor；
  • (\hat s)：context+target views 的平均 scale factor。

目标视图尺度通过：

[
\frac{s}{\hat s}
]

进行归一化。

理解边界：

该操作属于测试指标计算中的 camera-scale alignment，不应误解为训练阶段已知 GT camera pose，也不应与基础模型的单次前馈预测混为一谈。

它同时提醒我们：模型预测的场景坐标尺度不是天然固定的，评价时需要处理相对尺度差异。

3.11 Optional Post Optimization

【原文：Section 3.3】

前馈模型输出 Gaussian 和 camera parameters 后，可执行额外优化：

  1. 剪除 opacity 小于 0.01 的 Gaussian；
  2. 从输入视图相机位置渲染；
  3. 计算 MSE 与 SSIM；
  4. 对 Gaussian 参数和相机参数反向传播；
  5. 逐场景更新位置、尺度、旋转、opacity、颜色和相机位姿。

4.2 关键技术边界

1. 联合相机—几何误差耦合

Gaussian 中心由深度和相机反投影得到。

因此：

[
\text{Pose Error}
\rightarrow
\text{Unprojection Error}
\rightarrow
\text{Gaussian Center Error}
\rightarrow
\text{Rendering Error}.
]

相机预测和深度预测不能完全独立评价。

2. 绝对尺度并未由第一相机 identity 自动确定

将第一张相机设为 identity 固定了坐标系参考，但不意味着真实世界的 metric scale 已经被唯一恢复。

测试时仍需要相对尺度对齐。

3. VGGT 伪标签是重要依赖

AnySplat 的几何训练依赖预训练 VGGT：

  • 相机伪标签；
  • 深度伪标签；
  • 初始化权重。

因此，模型能力与教师模型的领域覆盖和错误模式密切相关。

4. 训练监督主要来自输入视图

训练不使用 novel-view target image 作为直接监督。

输入视图重建与教师几何约束可以提高泛化，但也留下一个问题：在观测覆盖不足的区域，模型预测的结构有多少来自真实观测，多少来自教师先验？

5. 单视图能力不能从“支持单视图输入”的文字直接推断

论文在 Method 中称可处理从单张图像到数百张图像，但训练设置每次采样 2–24 帧，主要实验也以 2、3、6、8、16、32、48、64、200-view 等多视图设置为主。

论文没有提供充分的独立单视图 NVS 定量实验。因此，不能把“支持单视图输入”直接等同于单视图下真实几何可恢复。

6. 视图数量增加并不代表几何证据一定增加

如果新视图与已有视图高度冗余，新增图像可能只增加计算量，而没有增加有效视差或可观测性。

体素化可以减少空间冗余 Gaussian，但不能把冗余视图转化为新的几何信息。

7. Voxelization 的离散 assignment

Eq. (5) 使用空间量化，Eq. (6)–(7) 对体素内属性进行可微聚合。

离散 voxel membership 本身并非处处可微。论文正文未详细说明跨 voxel assignment 边界的梯度处理。

8. 886M 参数与“轻量”不能混为一谈

论文强调 lightweight rendering head，但整体模型约 886M parameters。

所以“轻量”主要描述其渲染 Head 或逐场景重建流程相对轻量，不应直接理解为整个网络参数规模很小。

5.2 技术演进主线

5.3 PixelSplat → MVSplat：从概率式几何定位到显式匹配代价

PixelSplat 的主要技术思路：

  • 使用 Epipolar Transformer 聚合两视图信息；
  • 预测离散深度概率分布；
  • 通过概率采样确定 Gaussian 位置。

MVSplat 的主要增量：

  • 通过相机几何进行 Plane Sweep；
  • 显式构建 Cost Volume；
  • 使用特征相关性表达深度候选的匹配证据；
  • 将深度估计与 Gaussian 中心建立更直接的联系。

二者的共同前提是相机几何信息可用。

5.4 MVSplat → DepthSplat：从纯多视图证据到证据与先验融合

DepthSplat 保留 MVSplat 的 Cost Volume，但加入 Depth Anything V2 单目特征。

其核心问题是：

多视图匹配在低纹理、遮挡、反射等区域可能失效。

因此使用：

[
\text{Cost Volume}
+
\text{Monocular Features}
\rightarrow
\text{Depth Regression}.
]

它并没有放弃多视图几何，而是让单目先验补充多视图证据。

5.5 DepthSplat → AnySplat：研究设定发生了更根本的变化

两篇论文最重要的差异不是“是否使用单目特征”，而是相机参数是否作为输入已知条件。

DepthSplat：

[
\text{Images}+\text{Known Camera Parameters}
\rightarrow
\text{Depth}+\text{Gaussians}.
]

AnySplat：

[
\text{Uncalibrated Images}
\rightarrow
\text{Camera Parameters}+\text{Depth}+\text{Gaussians}.
]

因此 AnySplat 的问题更复杂：

  • 相机位姿未知；
  • 相机内参未知；
  • 深度未知；
  • Gaussian 中心依赖预测相机和预测深度；
  • 相机与几何的误差会互相传播。

5.6 AnySplat 不是简单的 MVSplat + VGGT

需要区分三个层次：

  1. 几何编码： AnySplat 使用 VGGT-style Geometry Transformer；
  2. 相机与深度预测： 联合预测相机参数、深度和 Gaussian；
  3. 训练监督： 使用 VGGT 产生伪几何先验，并通过 RGB、几何一致性和蒸馏损失训练。

因此，AnySplat 的核心是将几何基础模型的先验转化为可直接输出 Gaussian 场景的前馈重建模型。

5.7 四篇工作的共同边界

尽管四篇工作的输入设定不同，但它们共同面对：

  • 有限观测下的几何可辨识性；
  • 观测证据与学习先验之间的关系；
  • NVS 图像质量与真实几何准确性之间的差异；
  • 不同视图之间的外观一致性；
  • 模型对未观测区域的预测是否可信。

AnySplat 缓解了已知相机位姿这一输入限制，但没有自动解决稀疏观测下的几何可辨识性问题。

Research Problem 有限且受水下退化影响的观测证据，如何支持可靠、可辨识、具有不确定性意识的三维几何恢复
Method PixelSplat、MVSplat、DepthSplat、AnySplat 等具体技术路线

6.2 AnySplat 与水下稀疏观测的直接联系

AnySplat 最直接的启发是：

当相机位姿未知时，可以尝试从图像集合中联合估计相机、深度与三维场景，而不是将可靠标定作为前置条件。

这与水下实际采集存在联系：

  • 水下相机轨迹不一定规则；
  • 相机位姿可能受低纹理和弱匹配影响；
  • 图像可能来自临时采集而非预先标定的摄影测量流程；
  • 视图数量有限，且视角分布不均匀；
  • 水下图像可能存在颜色衰减、散射和对比度下降。

AnySplat 提供了一个 pose-free feed-forward 设计参照，但其现有实验并没有证明它能够直接处理水下成像。

6.4 研究问题一：水下退化条件下的相机—几何联合可辨识性

AnySplat 通过图像集合预测相机和几何。

但水下图像中，外观变化可能使几何与相机误差更加难以区分。

例如：

  • 相机位姿偏差会导致跨视图投影错位；
  • 水下传播导致的对比度变化会降低特征匹配；
  • 散射可能使远距离结构边界变得模糊；
  • 弱纹理可能使相机旋转和平移估计缺少可靠约束。

于是出现一个问题：

当前的匹配误差究竟来自相机估计错误，还是来自水下外观变化？

如果二者没有被区分，模型可能将成像退化误解释为几何结构变化。

可形成的研究问题

如何在稀疏水下观测中联合估计相机与几何，并显式区分位姿不确定性和水下外观变化造成的匹配不确定性？

6.5 研究问题二：VGGT 伪几何先验在水下场景中的可靠性

AnySplat 对 VGGT 的依赖包括：

  • Backbone 初始化；
  • Camera pseudo labels；
  • Depth pseudo labels。

因此，VGGT 不只是一个可替换的网络初始化工具，而是训练目标的重要来源。

如果 VGGT 在水下场景中存在域偏移，那么：

[
\text{Teacher Bias}
\rightarrow
\text{Pseudo-label Bias}
\rightarrow
\text{Student Geometry Bias}.
]

水下场景可能使教师模型：

  • 将悬浮颗粒理解为物体结构；
  • 将散射边界理解为表面边界；
  • 在低对比度区域产生不稳定深度；
  • 对水体颜色变化产生错误的结构响应。

可形成的研究问题

如何评估、校准并筛选基础几何模型在水下场景中的伪标签，使学生模型能够利用先验但不盲从先验？

6.6 研究问题三：观测证据与学习先验之间的可靠性融合

AnySplat 使用 VGGT 先验与自身渲染一致性训练。

DepthSplat 则显式融合多视图 Cost Volume 与单目特征。

两类方法都表明：几何恢复需要结合观测证据与学习先验。

但它们没有将以下问题作为核心研究目标：

  • 哪些区域具有充分多视图证据？
  • 哪些区域主要依赖先验？
  • 哪些区域的先验和观测相互冲突？
  • 当二者都不可靠时，是否应该拒绝输出确定几何？

在 Sparse-Observation Underwater Vision 中，这一问题尤其重要。

可形成的研究问题

如何在水下稀疏观测中估计多视图证据、基础模型先验和成像退化各自的可靠性，并将可靠性显式用于几何融合？

6.7 研究问题四：水下 RGB 自监督与几何—外观耦合

AnySplat 的 RGB loss 为：

[
\mathcal L_{\mathrm{rgb}}

\operatorname{MSE}(I,\hat I)
+
\lambda_1\operatorname{Perceptual}(I,\hat I).
]

该损失依赖渲染图像与输入图像之间的外观一致性。

但水下成像并不只是表面颜色与几何投影：

  • 直接光会随传播距离衰减；
  • 后向散射会引入路径相关的背景光；
  • 水体颗粒会影响局部可见性；
  • 不同视角的传播路径可能导致外观变化。

如果渲染模型不能解释这些因素，模型可能通过调整 Gaussian 几何、颜色和 opacity 来补偿外观误差。

这可能导致：

[
\text{Underwater Appearance Error}
\rightarrow
\text{Geometry / Gaussian Compensation}.
]

这是从 AnySplat 训练目标迁移到水下场景时需要检验的研究假设，不是 AnySplat 原文已经证明的结论。

6.8 可形成的 Research Problem 候选

RP-1：Sparse Underwater Observation 下的 Pose–Geometry Joint Uncertainty

问题：

在水下图像数量有限、外观退化且相机位姿未知时，如何联合估计相机与场景几何，并显式表达二者的联合不确定性？

研究重点：

  • 位姿误差如何传播到深度和 Gaussian 中心；
  • 不同视图基线如何影响几何可观测性；
  • 弱纹理和散射如何影响位姿估计；
  • 如何区分 pose uncertainty 与 depth uncertainty；
  • 何时应拒绝生成确定的三维结构。

与 AnySplat 的关系：

继承其联合 Camera + Depth + Gaussian 前馈框架，但研究重点从确定性预测转向可辨识性和不确定性。

RP-2：水下基础几何模型的伪标签可靠性校准

问题：

如何在水下场景中评估和校准预训练几何模型的深度与相机伪标签，避免域偏移导致错误几何监督？

研究重点：

  • 教师模型在不同能见度下的可靠性；
  • 伪标签置信度与真实误差之间的关系；
  • 教师与多视图观测冲突时如何处理；
  • 伪标签错误是否会被学生模型放大；
  • 如何在不同水体条件之间迁移。

与 AnySplat 的关系：

直接对应其 VGGT pseudo-label knowledge distillation，但将教师可靠性本身作为研究对象。

RP-3：水下稀疏多视图中的观测证据—先验自适应融合

问题：

如何在水下稀疏观测中，依据实际几何证据和先验可靠性动态决定深度预测来源？

研究重点：

  • 多视图匹配置信度；
  • 单目 / 基础模型先验置信度；
  • 观测与先验冲突检测；
  • 不可观测区域识别；
  • 可靠性校准与不确定性输出。

与 DepthSplat、AnySplat 的关系：

DepthSplat 提供 Cost Volume + Monocular Feature 的融合范式；AnySplat 提供 VGGT 几何先验与相机联合预测范式。RP-3 将二者统一到证据可靠性建模问题中。

RP-4：水下成像感知的无深度标签几何预训练

问题：

如何利用大量未标注水下多视图图像学习可迁移的三维几何表示，同时避免标准 RGB 渲染目标把介质外观误差转化为几何偏差？

研究重点：

  • 水下光传输与可微渲染；
  • RGB self-supervision 的几何有效性；
  • 介质外观与场景表面的解耦；
  • 多视图深度一致性；
  • 伪标签与渲染监督之间的互补关系。

与 AnySplat 的关系：

继承其 RGB-only training + pseudo-geometry distillation 思想，但重新检验训练目标在水下成像中的物理适用性。

7. 最终知识内化

7.1 用一段话解释 AnySplat

AnySplat 是一个面向未标定多视图图像集合的前馈式 3D Gaussian 重建框架。它使用 DINOv2 patch tokens 和 VGGT-style Alternating-Attention Geometry Transformer 编码多视图信息，再通过 Camera、Depth 和 Gaussian 三个 Head 联合预测相机内外参、逐像素深度和 Gaussian 属性。预测深度结合相机参数反投影为 Gaussian 中心，之后通过 Differentiable Voxelization 将空间上接近的像素级 Gaussian 聚合为体素级 Gaussian。训练阶段使用输入图像 RGB 重建损失、Depth Head 与 Gaussian 渲染深度之间的几何一致性损失，以及 VGGT 提供的伪相机和伪深度蒸馏损失。这样，模型不需要真实 3D 标注或预先给定相机标定，也能在前馈推理中完成从稀疏到密集视图的场景重建。

7.2 最重要的六点

  1. AnySplat 的核心变化是 pose-free。 不再要求用户预先提供相机内外参，而是联合预测 Camera、Depth 和 Gaussian。
  2. 它高度依赖 VGGT 几何先验。 VGGT 同时参与初始化和伪标签监督。
  3. 训练不是无监督意义上的“没有任何几何监督”。 它没有真实 3D 标签，但有 VGGT pseudo camera / pseudo depth。
  4. Voxelization 解决的是 Gaussian 数量和渲染规模。 它不自动解决 Transformer 输入 token 的全部扩展成本。
  5. 基础模型与 post-optimization 必须分开评价。 后优化结果不能直接作为纯前馈模型指标。
  6. Pose-free 不等于几何可辨识。 相机估计与几何仍可能存在不确定性，尤其在稀疏观测、弱纹理和水下退化条件下。

本篇论文将研究问题从“已知相机条件下如何更好地恢复几何”推进到：

3.13 研究背景与 Related Work

3.13.1 Optimization-based Novel View Synthesis

作者回顾两类典型神经渲染方法：

NeRF 系列

  • 使用坐标网络表示连续密度与辐射场；
  • 通过体渲染生成 Novel Views；
  • 可以取得较高渲染质量；
  • 但训练和渲染开销较高。

3D Gaussian Splatting

  • 使用显式各向异性 Gaussian 表示场景；
  • 通过可微 rasterization 渲染；
  • 使用 adaptive density control 优化几何细节；
  • 使用 spherical harmonics 表示 view-dependent appearance；
  • 可以实现实时或接近实时渲染。

作者指出，这类方法通常依赖准确相机位姿，通常通过 COLMAP 等 SfM 工具获得，因此存在相机注册和逐场景优化的预处理成本。

3.13.2 Joint Camera and Scene Optimization

有些方法试图联合优化相机位姿和场景表示，但作者认为它们仍存在限制：

  • 依赖增量图像序列和相机内参；
  • 适用场景可能限制在较小运动范围；
  • 或只适合稀疏视图覆盖；
  • 仍然需要冗余的逐场景优化。

AnySplat 的目标是把相机估计和场景表示统一到一个前馈网络中。

3.13.3 Pose-aware Generalizable Reconstruction

作者将 generalizable 3D reconstruction 分成 pose-aware 与 pose-free 两类。

Pose-aware 方法假设输入图像的相机参数已知。

作者列举的方向包括：

  1. 直接预测 3D Gaussian 的方法；
  2. 不显式输出 3D 表示、直接预测 Novel View 的 neural network；
  3. LRM architecture family。

这类方法减少了逐场景优化，但相机参数仍然是输入前提。

3.13.4 Pose-free Generalizable Reconstruction

Pose-free 方法只使用图像作为输入，并通常联合预测相机与几何。

作者讨论了：

  • DUSt3R；
  • MASt3R；
  • VGGT；
  • CUT3R；
  • 其他基于 Transformer 的 pose-free geometry models；
  • NoPoSplat、FLARE 等 pose-free NVS 方法。

作者认为几何基础模型在稠密点云和相机估计方面表现突出，但在纹理质量和多视图几何一致性方面仍有不足；另一类 pose-free NVS 方法则主要适用于 sparse-view setting。

AnySplat 的定位是把 pose-free geometry foundation model 的几何能力与 Gaussian rendering 结合起来，并通过 voxelization 扩展到 dense-view。

3.14 评价指标与实验协议

3.14.1 NVS Metrics

作者使用：

  • PSNR；
  • SSIM；
  • LPIPS。

这些指标比较预测 Novel View 与 GT 图像的视觉差异。

它们评价的是渲染图像质量，不直接等价于三维几何准确性。

3.14.2 Pose AUC

作者使用 AUC 评价相对图像位姿准确性，并报告阈值：

  • AUC@5；
  • AUC@10；
  • AUC@20；
  • AUC@30。

原文说明 AUC 衡量不同角度阈值下 accuracy curve 的面积，但本报告不在原文没有明确给出的地方补充其完整实现细节。

3.14.3 Absolute Relative Error

[
\operatorname{AbsRel}

\frac{1}{M}
\sum_{i=1}^{M}
\frac{|\hat D_i-D_i|}{D_i}.
\tag{12}
]

其中：

  • (D_i)：参考深度；
  • (\hat D_i)：预测深度；
  • (M)：参与评价的像素数量。

AbsRel 越低越好。

3.14.4 (\delta_1) Accuracy

[
\max\left(
\frac{\hat D_i}{D_i},
\frac{D_i}{\hat D_i}
\right)<1.25.
\tag{13}
]

(\delta_1) 表示满足上述比例阈值的像素比例，越高越好。

因此，本文的主要实验覆盖从少量输入到数百输入的场景，但没有系统展示 1-view 下的几何恢复性能。

3.14.6 Dense-view Baseline 的初始化

作者说明，COLMAP 在稀疏视图条件下经常不可靠，因此 dense-view 的 3D-GS 与 Mip-Splatting baseline 使用 VGGT 对输入图像进行 calibration，并生成 point cloud 作为初始化。

因此，比较的是：

  • AnySplat：前馈相机和 Gaussian 预测；
  • 3D-GS / Mip-Splatting：VGGT 初始化 + per-scene optimization。

这并非“完全不使用预训练几何模型”的 baseline 比较。

4.4 原文内部一致性与实验协议核查

以下是根据同一论文不同章节之间的对照形成的独立核查。

4.4.1 训练时长表述存在差异

Introduction 的贡献描述称，训练流程在 8–16 GPUs 上可在一天以内完成。

Section 4.1 Implementation Details 则报告：

  • 16 张 NVIDIA A800；
  • 约两天训练时间；
  • 15K iterations。

论文没有解释两处时间表述之间的差异。

因此，引用训练成本时应优先保留实现细节中的具体报告，并注明 Introduction 的表述不同。

4.4.2 Sparse-view 定义与 16-view 设置

Table 1 Caption 将 sparse-view 描述为输入图像少于 16 张，但表格中包含 16 Views 一列。

因此，严格按数学不等式理解时，16-view 不属于 fewer than 16；论文实际实验分类更接近将 16-view 也纳入 sparse-view 组。

4.4.3 Table 1 并非所有设置全面领先

  • Mip-NeRF360 3-view：AnySplat PSNR 16.20，略低于 NoPoSplat 的 16.36；
  • Mip-NeRF360 64-view：AnySplat PSNR 21.15、SSIM 0.589，低于 3D-GS 和 Mip-Splatting；
  • 同一 64-view 设置中，AnySplat LPIPS 仍然更好。

因此，“outperforms”需要结合具体数据集、视图数量和指标理解，不能解释为每个指标均最优。

4.4.4 Table 2 的 1K post-optimization 指标存在权衡

AnySplat 基础模型 LPIPS 为 0.446，1000-step post-optimization 后 LPIPS 为 0.519，反而变差；PSNR 和 SSIM 则提高。

3000-step 后三项指标才都优于基础模型。

这说明 post-optimization 的收益依赖优化步数和指标，并非每个阶段都同步改善所有视觉指标。

4.4.5 Table 3 中基础模型与优化式方法的比较

基础 AnySplat：

  • PSNR 低于 InstantSplat-VGGT；
  • SSIM 略低；
  • LPIPS 更好；
  • 时间明显更短。

只有加上 1K post-optimization 后，三项 NVS 指标才全面超过 InstantSplat-VGGT。

因此，应区分 feed-forward quality 与 optimized quality。

4.4.6 训练采样使用相机位姿距离

论文称模型训练不需要真实相机位姿监督，但在 unordered datasets 的 view sampling 中，明确使用相机 pose distance：

  • 随机选一个 reference frame；
  • 计算其他帧到 reference 的 pose distance；
  • 根据预设距离阈值采样视图。

因此，需要区分：

  1. 模型输入和损失监督： 不要求真实 camera pose label；
  2. 训练数据采样辅助： 对部分数据集使用 pose metadata 计算视图间距离。

“训练不使用位姿信息”如果被理解为训练 pipeline 的任何环节都不读取 pose metadata，就不准确。

4.4.7 Test-time pose alignment 的评价边界

论文在计算 rendering metrics 时，使用 context views 和 target views 的联合信息估计 scale factor。

因此，评价协议包含额外的 target-view scale alignment。它不是训练阶段的 GT pose supervision，但也不应与完全只依赖 context views 的 pose evaluation 混为一谈。

4.4.8 Confidence 不等于校准不确定性

论文使用：

  • (C_i^D) 选择高置信度深度像素；
  • (C_g) 进行 voxel 内 Gaussian 加权。

这些 confidence 被用于模型内部筛选和聚合，但论文没有系统验证其是否与真实深度误差或几何不确定性概率校准一致。

4.4.9 体素化不等于解决全部密集视图复杂度

Figure 5 主要验证 Gaussian 数量和渲染显存的增长受到抑制。

但 Geometry Transformer 的 Global Attention 输入仍然包含所有视图的 tokens。体素化发生在 Gaussian 预测之后，不会直接消除输入 token attention 的计算成本。

因此，作者关于 dense-view scalability 的结果应理解为对 Gaussian representation / rendering scaling 的改善，而不是整个网络计算复杂度已经完全饱和。

4.4.10 单视图输入的证据不足

Method 文字提到从单张图像到数百张图像，但训练采样从 2–24 帧开始，主要 NVS 定量实验也没有专门的 1-view benchmark。

单视图下的三维结构需要较强先验，无法仅凭“模型支持单视图输入”的表述证明真实几何可辨识。
